## 二、本版能力取舍原则（r3：原能力对照表已删除，结论沉淀于此，不含任何外部产品信息）

1. **已领先的能力只加固不重写**：结算算法自检（`validatePlan`）、本地权威 + Outbox + LWW 云同步、局域网离线协同——全部保持现状，本版只做加固（G6 加密）。
2. **缺的是「表达与形态」**：本版补三类能力——结算结果的表达（S5 分享卡）、账本形态缺口（S4 个人账本）、分摊模式缺口（S3 百分比）。
3. **三个结构级差异点全部自研**：公款池（S8）、记账收件箱（S10）、协作可观测性（S12）。三者都是既有架构（净额结算 / 独立暂存 / LWW 合并）的自然延伸，**不引入并行体系、不另建通道**。
4. **借鉴仅限能力形态层面**（§〇 红线）：所有代码、文案、视觉均为原创；「同类产品有此功能」不构成任何实现的充分或必要依据。
5. **「不做」清单与理由见 §1.2**；各阶段内的进一步取舍见对应章节的「目标与定位」与「禁止事项」。

## 三、全局工程约定（所有阶段强制遵守）

### 3.1 不可动摇的架构基线

| 约定 | 内容 | 违反后果 |
|---|---|---|
| 金额口径 | 一律 `int` 分存储；`normal` / `prepay` 为正、`refund` 为负（下行合流对 refund 套 `-abs()` 幂等归一，`core/money.dart`）；仅展示层格式化 | 直接判定验收失败 |
| 读数幂等归一 | 读取边界统一 `sign = type == 'refund' ? -1 : 1`，**同时**施加到 `amountCents` / `payers` / `shares` 三处（现状：`ledger_providers.dart` 的行→记录转换已实现） | 结算/统计口径错乱 |
| 算法层纯净 | `lib/domain/` 全部纯 Dart，无 IO、无 Flutter 依赖，可被 `flutter test` 完全覆盖 | 违反即返工 |
| 写入即同步 | 每个写操作后 `SyncOutboxService.notifyWrite(localKey, id[, op:'delete'])`；删除发墓碑；`localKey` 一律取 `SyncEntity.localKey`（snake_case），**禁止用枚举 `name`**（历史 bug H10） | 云同步与局域网不一致 |
| 事务与通知顺序 | 写方法一律**事务提交成功后**再 `notifyWrite`（V2.6.6.2 §0.3.4） | 事务回滚后仍上行，产生幽灵数据 |
| 单一桥接层 | 账本 UI 只通过 `ledger_providers` 族访问数据层。现状核对：屏幕层唯一例外是 `space_detail_screen.dart` 直连 `travel_spaces_repo`（空间域、非账本域），**不扩入 G4 治理范围**；本版新增 UI 一律走 providers | 破坏分层 |
| 金额展示 | 禁止在屏幕层手工拼接金额字符串，统一走 `shared/widgets/money_text.dart` 的 `MoneyText` / `core/money.dart` 的 `formatMoney` | 展示口径不统一 |
| 主题与动效 | 颜色一律 `ColorScheme` 语义色 + `theme/tokens.dart` 既有令牌（`AppRadius` / `Spacing` 等），禁止硬编码色值；动效适配 `prefers-reduced-motion`（现状在 `today_cockpit_screen.dart` 有先例） | 可访问性回归 |

**members 实体的 LWW 时间口径（G1 相关，必须知悉）**：`Members` 表**没有 `updatedAt` 列**，同步层以 `createdAt` 承载 `updated_ms`（`sync_codec.dart` 头注、`sync_merger.dart` 头注）。因此 S2 的 `members.archived` **随整行 LWW 合并**，**不得**为 members 新增 `updatedAt` 列（会改变全部成员行的时间语义）。

## 七、S3 · B1 百分比分摊（自动归一）

### S3.1 目标与定位

`ShareMode` 新增 `percent`，采用**自动归一**策略（Σ≠100% 时按比例归一，不报错、不拒绝保存）。

### S3.2 数据契约

- **复用 `expenses.portionsJson`**（不新增列）。
- 存储形态：`{"<memberId>": <bp>}`，`bp` 为**万分比基点整数**（10000 = 100%），归一后 **Σbp 恒等于 10000**。
- 判别：`shareMode == 'percent'` 决定 `portionsJson` 语义（`portions` 存份数整数，`percent` 存 bp）。此语义重载**必须在代码注释与本节显式标注**。
- **禁止**在 `portionsJson` 中写入浮点数或百分号字符串。

### S3.3 算法规格（纯函数，置于既有 `lib/domain/share_splitter.dart`）

**(1) 归一化 `normalizePercentToBp(Map<String,int> raw) → Map<String,int>`**

```
1. 剔除 bp <= 0 的成员
2. 结果为空集 → 返回空 Map（调用方回退 equal，与 portions「全 0 回退 equal」口径一致）
3. total = Σ inputBp（允许任意正整数，无需先等于 10000）
4. exact_i = inputBp_i × 10000；base_i = exact_i ~/ total；rem_i = exact_i % total
5. deficit = 10000 − Σ base_i；按 rem_i 降序逐个 +1 直至归零；平局按 memberId 字典序升序
6. 返回 Σ == 10000 的结果
```

**(2) 分摊 `splitByPercent(totalCents, percents) → List<ShareEntry>`**

```
sign = totalCents.isNegative ? -1 : 1；abs = totalCents.abs()
exact_i = abs × bp_i；base_i = exact_i ~/ 10000；rem_i = exact_i % 10000
deficit = abs − Σ base_i；按 rem_i 降序 +1 补足，平局按 memberId 字典序
每项 × sign；断言 Σ 结果 == totalCents（含负数场景）
```

**红线**：全流程只用整数运算，禁止 `double`。

## 九、S8 · N1 公款池（旅行基金）

> r2 将本阶段提前至 S4 之后（P0 主线）。前置：S1（表）、S2（闸门/桥接）、S4（kind 分流）。

### S8.1 目标

「出发前每人交一笔公费、途中统一支出、结束按剩余退回」在芥舟内闭环。**纳入现有结算体系**，不建独立对账通道。

### S8.2 核心建模（红线，不得改动）

**约定**：公款池 = 入金账单（缴款人付款）+ 出金账单（管理人为 payer）。

| 方向 | type | payers | shares | `fund_id` |
|---|---|---|---|---|
| **入金** | `prepay` | 各缴款人，金额 = 各自缴纳额 | **管理人，金额 = 缴纳总额** | 非空 |
| **出金** | `normal` | **管理人，金额 = 本次支出** | 按 `shareMode` 分摊到参与人 | 非空 |

**为什么入金必须是「缴款人 payer、管理人 share」**（4 人各交 1000 给张三、途中吃饭 300 从公费出）：

| 建模 | 入金净额 | 出金净额 | 合计 | 结算结果 |
|---|---|---|---|---|
| 缴款人 payer（**正确**） | 四人各 +1000，张三 −4000 | 张三 +300，四人各 −75 | 四人各 **+925**，张三 −3700 | 张三退每人 925 ✅ |
| 管理人 payer（**错误**） | 张三 +4000，四人各 −1000 | 张三 +300，四人各 −75 | 张三 +4300，四人各 **−1075** | 四人各给张三 1075 ❌ |

正确建模下 `settle_engine` / `validatePlan` **零改动**即自动得出退款方案。**口径红利**：入金用 `prepay`（统计口径排除 prepay，入金不是消费）；出金用 `normal` 正常计入总支出。

### S8.3 表结构与约束

- `Funds` / `expenses.fund_id`（S1 已建）。
- 约束（repo 层强制校验）：
  - 一池**唯一管理人**（`managerMemberId` 非空）；可转移（只改 `Funds` 一行 + `notifyWrite`，**不改历史账单**）。
  - `targetCents`（计划收款总额）**可空**，不强制。
  - 管理人成员**不可被归档**，除非先转移管理人（与 S2.1 `archiveMember` 联动校验）。
  - 池 `status = closed` 后**禁止**再新增入金/出金账单。

### S8.4 池余额（派生量，不入库；r2 补全口径）

新增纯函数 `lib/domain/fund_calculator.dart`：

```
fundBalanceCents(fundId, List<ExpenseRecord>) -> int
  = Σ(type==prepay 且 fundId 匹配 且 settledRoundId==null)
  − Σ(type==normal 且 fundId 匹配 且 settledRoundId==null)
  ⚠️ r2 裁定：只统计未入账账单。含池账单的结算轮完成后，已退款部分自然退出余额，
     关池前余额趋近 0；否则已退款金额会被重复显示。

fundContributionByMember(fundId, List<ExpenseRecord>) -> Map<memberId, int>
  = 未入账入金账单的 payers 逐人累加

fundSpentByCategory(fundId, List<ExpenseRecord>) -> Map<categoryKey, int>
  = 未入账出金账单按分类聚合
```

**红线**：余额是**展示量**，「谁该退多少」由结算引擎负责——两套数字不得互相替代，余额不得写入数据库。

### S9.2 算法规格（r2 定位：新文件，不碰引擎本体）

新增 `lib/domain/settle_strategy.dart`（`settle_engine.dart` **一行不动**）：

```
enum SettleStrategy { minTransfers, minParticipants }

SettlePlan buildPlan({
  required Map<String,int> balances,
  required SettleStrategy strategy,
})
```

- `minTransfers` → 直接调用既有 `minTransferPlan`（行为**逐位不变**）。

2. 仅本地：不登记 `SyncEntity`，不上云、不进快照、不进备份。
3. 可见性：仅 `owner` 与 `editor` 可查；`viewer` 入口不渲染（隐藏不置灰）。
4. UI：新路由 `/expenses/audit`（变更记录页），按时间倒序，支持按 账单/成员/结算 筛选；入口 = `ledger_home_screen` AppBar 溢出菜单（`PopupMenuButton`，仅 owner/editor 渲染）+ 桌面工作台侧栏工具区（§3.4）。
5. 体积控制：单团保留最近 **2000 条**，超出按 `atMs` 裁剪最旧（写入后异步检查）；本地索引 `(group_id, at_ms DESC)`。
6. `actorMemberId` 无对应本地成员时显示「未知成员」，不得崩溃。

**验收（≥8）**：各写操作产生对应记录；只含变更字段；viewer 无入口；记录不出现在任何同步与备份路径；超 2000 条按策略裁剪且不影响业务数据；actor 缺失降级显示；同一操作重试不产生重复记录；关闭审计开关后停止写入（若提供开关则默认开）。

### S12.4 禁止事项

- 禁止为冲突回执保存被覆盖版本体。
- 禁止让冲突检测改变合并结果。
- 禁止把 `audit_logs` / `conflict_records` 登记为 `SyncEntity` 或写入任何云端表。
- 禁止在审计记录保存完整账单快照。
- 禁止向 viewer 暴露审计入口。

## 二十、附录 · 术语与口径速查

| 术语 | 定义 |
|---|---|
| `bp` | 万分比基点，10000 = 100%；百分比分摊存储单位 |
| `kind` | 账本类型：`travel`（默认）/ `personal`；`loan` 预留不开放 |
| `archived`（members） | 成员软删除标记；不进选择器，**照常参与历史净额**；行级 LWW 以 `createdAt` 承载 |
| `settledRoundId` | 账单结算归属指针；真实轮 id 或 `"manual"`；null = 未结 |
| `expenseIdsJson` | 结算轮创建时快照的账单 id 列表；完成/撤销结算的回写依据 |
| `fund_id` | 账单所属公款池；**非空即属池** |
| 管理人 | 公款池唯一负责人（`manager_member_id`）；可转移，不可多设 |
| 入金 | `type = prepay`，payer = 缴款人、share = 管理人 |
| 出金 | `type = normal`，payer = 管理人、share 按分摊模式 |
| 池余额 | Σ未入账入金 − Σ未入账出金；**派生展示量**，不入库、不参与净额 |
| `inbox_items` | 记账收件箱独立暂存表；pending 条目**不得**参与任何金额口径 |
| `converted_expense_id` | 归类幂等键；已存在则跳过写入，防重复账单 |
| 冲突回执 | LWW 覆盖的**本地只读观测记录**（判定：本地有 pending 且云端胜）；不存版本体、不上云 |
| 审计轨迹 | 本地变更链；只记字段名与变更后值；owner/editor 可见；单团 2000 条 |
| `payMethod` | 支付方式纯标签；不跟踪余额，不参与净额与分摊 |
| `SettleStrategy` | `minTransfers`（默认，逐位不变）/ `minParticipants` |
| 警告式校验 | 保存按钮不禁用，点击后按序提示第一个问题（既有交互取舍） |
| 隐藏不置灰 | 无权限入口直接不渲染（V2.6.6.2 确立原则） |
| 黄金样本 | 验证重构前后口径逐位不变的固定账单集与预期值 |
| 防回声风暴 | 加入方只广播无 port 纯询问包（1100ms × ≤12 次）；主机只对纯询问单播回执 |
| 三宿主 | 账本 UI 的三个载体：移动主页 / 桌面工作台 / 旅伴空间账本区（§3.4） |
| `N0` | S1.0 实测的测试基线总数；门禁总数 = N0 + 164 |
