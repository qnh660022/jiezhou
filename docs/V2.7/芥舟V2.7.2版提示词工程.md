| 概念 | 本质 | 数据层 | 进入方式 | 离开方式 |
|---|---|---|---|---|
| 想去池 | 候选存储区，条目**无日期** | `WishlistItems` 表（独立新表） | 攻略「先想去」/ 大纲纯标题行 / 装配页手动表单 | 装配落卡 / 池内手动「排到第 N 天」（落卡**即移出池**） |

**四条收口规则（违反任一条即该阶段验收失败）**：
1. 想去池条目落卡后**即从池中移除**（同事务内删池行 + 建卡行），不得两边同时存在；
2. Plan B **不自动回流**想去池；仅提供手动「退回想去」（删卡 + 入池）；
3. 攻略条目动作**有且仅有两个**：「直接排」「先想去」，不得出现第三动词；
4. 装配台 UI 必须标注「来自想去池」，不得呈现为独立存储区。

### 2.2 不可动摇的架构基线

| 约定 | 内容 | 违反后果 |
|---|---|---|
| 金额口径 | 一律 `int` 分；`refund` 负数冲减；仅展示层格式化（`MoneyText`/`formatMoney`） | 验收失败 |
| 日期口径 | 行程域一律 `epochDay`（本地日，`core/date_utils.dart`）；星期计算必须走 S12 新增的 `weekdayCnOf`，禁止手写 `DateTime.now()` 推算 | 跨设备日期漂移 |
| 算法层纯净 | `lib/domain/` 全部纯 Dart，无 IO、无 Flutter、无时钟直读（时间由参数注入） | 违反即返工 |
| 写入即同步 | 每个写操作后 `SyncOutboxService.notifyWrite(localKey, id[, op:'delete'])`；删除发墓碑；`localKey` 一律取 `SyncEntity.localKey`（snake_case），禁止用枚举 `name`（历史 bug H10） | 云同步静默丢失 |
| 事务与通知顺序 | 写方法一律事务提交成功后再 `notifyWrite`；批量操作在事务外逐行补发 | 幽灵数据 |
| 单一桥接层 | 行程 UI 通过 `trips_repo.dart` 及本版新增的 `wishlist_repo.dart` 访问数据层；新增 UI 禁止直连 DAO | 破坏分层 |
| 主题令牌 | 颜色一律 `ColorScheme` 语义色 + `theme/tokens.dart` 既有令牌，禁止硬编码色值 | 可访问性回归 |

## 五、S2 增减天数顺延引擎（A1）

### 5.1 目标与定位

修复正确性缺陷：现状修改 `Trips.startEpochDay/endEpochDay` 后，`TripItems.dateEpochDay` 归属脱节。本阶段提供纯函数引擎 + 详情页入口，让插/删一天时全局一致平移。

### 5.2 涉及文件清单

| 动作 | 文件 | 内容 |
|---|---|---|
| 新建 | `lib/domain/day_shift_engine.dart` | 纯函数引擎（无 IO，时间不注入——本引擎只用 epochDay 整数） |
| 修改 | `lib/data/repo/trips_repo.dart` | 新增 `applyDayOps`（事务批量执行 + 逐行 notifyWrite） |
| 修改 | `lib/features/trips/widgets/`（新建 `day_ops_sheet.dart`） | 插入/删除弹层（三宿主共用） |
| 修改 | `lib/features/trips/screens/trip_detail_screen.dart`、`desktop_trips_workbench.dart` | 时间轴头部日期栏挂两个动作 |
| 新建 | `test/domain/day_shift_engine_test.dart` | ≥12 单测 |

### 5.3 算法规格

记 `dayIndex = dateEpochDay − startEpochDay + 1`，`target = startEpochDay + k − 1`（第 k 天）。

```dart
/// 全部函数为纯函数：输入行程天数 N 与卡列表快照，输出【变更动作列表】，
/// 由 repo 层在同一事务内执行（先改行，后改 Trips，提交后逐行 notifyWrite）。
sealed class DayOp {}
class OpShiftItem  extends DayOp { final String itemId; final int newEpochDay; }
class OpDeleteItem extends DayOp { final String itemId; }        // 物理删 + 墓碑
class OpSetEnd     extends DayOp { final int newEndEpochDay; }

/// 在第 k 天后插入一个空天（k 允许 0..N，0=最前）：
///   dateEpochDay >= start+k 的卡全部 +1；endEpochDay += 1。
List<DayOp> insertDay({required int startEpochDay, required int endEpochDay,
    required List<TripItemRecord> items, required int k});

/// 尾部追加一天：仅 endEpochDay += 1。
List<DayOp> appendDay({required int endEpochDay});

/// 删除第 k 天（1..N，N>=2），mode 三选一：
///   shift  ：target 当天卡 → target+1（sortOrder 追加该天末尾，步长 10 续编）；
///            随后 dateEpochDay > target+1 的卡各 -1。
///   merge  ：target 当天卡 → target-1（追加 sortOrder）；dateEpochDay > target 各 -1。
///            k==1 时禁用 merge（调用方 UI 不得提供该选项）。
///   discard：target 当天卡物理删除（OpDeleteItem）；dateEpochDay > target 各 -1。
/// 三种模式最终都 OpSetEnd(endEpochDay - 1)。
List<DayOp> removeDay({required int startEpochDay, required int endEpochDay,
    required List<TripItemRecord> items, required int k, required RemoveMode mode});
```

规则细节（逐条验收）：
1. 备胎卡（`backupOf` 非空/非''，S8 引入）与正式卡**同规则平移**，不区分处理；
2. `shift/merge` 的被承接卡 sortOrder = 目标天当前最大 sortOrder + 10 起按原相对顺序续编；
3. `discard` 产生的 `OpDeleteItem` 必须逐行写墓碑（`notifyWrite(localKey, id, op:'delete')`）；
4. N=1 时 `removeDay` 直接抛 `StateError('至少保留一天')`（UI 禁用入口）；
5. 引擎不改 `startEpochDay`（起点固定，只有 end 平移）。

### 5.4 UI 规格（三宿主）

- 移动端：时间轴头部日期栏右侧新增溢出菜单「插入一天…」「删除此天…」；「插入」弹天序选择列表（第 1..N 天后 + 最末）；「删除」弹三选一（k=1 时前合并项禁用），弹窗正文列明「将影响 X 张安排卡」；
- 桌面：Workbench 右栏同组件（`day_ops_sheet.dart` 以 `openAsDialog` 打开）；
- 空间：editor 可用；viewer 不渲染入口（隐藏不置灰）；
- 删除确认文案必须原创，含被删/被移动卡数。

### 5.5 测试用例清单（≥12）

1. 插入 k=0 / k=N / k=N+1 的全量平移正确性；
2. 删首天（k=1）：merge 禁用、shift 与 discard 正确；
3. 删末天（k=N）：shift 无后移对象、end 正确 -1；
4. 删中间天三种模式逐卡断言；
5. N=1 抛异常；
6. 备胎卡随平移；
7. sortOrder 续编（目标天原 10,20 → 承接后 30,40）；

### 6.3 文法定义（实现依据，逐条可测）

```
document   := line*                       空行（仅空白字符）忽略
line       := dayHeader | itemLine | 无效行
dayHeader  := ^\s*"D" digits \s* ["："|":"]? \s*$        设定当前天（后续 itemLine 归该天）
itemLine   := [time \s+] name [ \s+ duration]
time       := HH:mm（两位小时两位分钟，00:00–23:59）     → startTimeMin = h*60+m
duration   := digits["."digits]"h" | digits"m" | "半天" | "一天"
              → h 值*60（1.5h=90）；m 为整分钟；"半天"=240；"一天"=480
name       := 去除已匹配前缀/尾缀后的非空剩余文本          → 卡名（trim）
无效行     := 无法解析出非空 name 的行                    → 原样进导入报告
```

解析细则（逐条验收）：
1. `D3`、`D3：`、`D3:` 均合法；dayHeader 上的其余文本忽略；
2. 未出现任何 dayHeader 前的 itemLine → **不建卡，进想去池**（携带已解析的 time/duration；S6 未交付前计入导入报告的「入池挂起」计数）；
3. 尾缀时长取**最后一个**匹配 token（`西湖 2h 半天` → 240）；
4. 同名同天（name trim 后全等）已存在 → 跳过，计入「重复跳过」；
5. `HH:mm` 必须两位小时两位分钟；`9:30` 属无效行（防误吞名字）；
6. 解析器无任何正则回溯风险：单遍逐行、token 前缀匹配。

### 6.4 导出格式（对称，唯一真源是解析器同文件）

- 行序：按天（startEpochDay 起连续到 endEpochDay），天头 `D1`…；每天内按 `sortOrder`；
- 行格式：有 startTimeMin → `HH:mm 名称[ 时长]`；无时间 → `名称[ 时长]`；无时长省略尾缀；
- 时长输出规则：能整除 60 且 ≥60 → `Xh`（90 → `1.5h`）；<60 → `Xm`；240/480 特判输出 `半天`/`一天`；
- 想去池、备胎卡**不出现在导出**；
- 导出为纯文本（`\n` 分隔），用于填充文本域与复制。

### 6.5 交互规格（三宿主）

- 「大纲」页签结构：上部多行文本域（等宽字体，初值 = 导出文本），下部操作条；侧栏（≥600px 宽度时右栏，移动端折叠为抽屉）常驻想去池迷你列表；
- 「导入」→ 模式选择弹层：`追加` / `覆盖整程`；
  - 追加：按 6.3 规则建卡 + 入池，完成后展示导入报告（新增 N / 跳过重复 M / 无效 K【原样列出】/ 入池 J）；
  - 覆盖整程：强确认弹窗（列明「将删除 X 张卡并按大纲重建 Y 张」+ 明示不可恢复 + 需勾选「我已了解该操作不可恢复」才可点击确认）→ 事务内：删全部旧卡（逐行墓碑）→ 建新卡 → 报告；
- 空间：editor 可导入；viewer 文本域只读、无导入按钮；
- 文案原创；适配 `prefers-reduced-motion`。

### 6.6 测试用例清单（≥16）

1. 三种天头写法；2. 时间解析与越界（24:00 无效）；3. `2h/90m/1.5h/半天/一天` 五种时长；4. 尾缀取最后；5. 无天头行进池；6. 同名同天跳过；7. `9:30` 无效行；8. 空文档；9. 仅天头；10. 多天混排乱序（按文档顺序落卡）；11. 导出-导入 round-trip 逐卡一致；12. 覆盖模式字段重建一致；13. 中文名含空格/emoji；14. 半角全角冒号；15. 超长行（1000 字符）不崩；16. CRLF 与 Tab 输入。

### 10.2 算法规格（`lib/domain/assemble_engine.dart`，纯 Dart）

```dart
/// 容量档（分钟）
const Map<TripPace, int> kDayCapacity = {
  TripPace.relaxed: 360, TripPace.standard: 480, TripPace.tight: 600 };

/// 类型×时段窗（分钟制，闭开区间 [from, to)），附录 T2
const Map<String, (int, int)> kTypeWindow = {
  'attraction': (420, 1140), 'food': (390, 1290),
  'transport': (0, 1440), 'stay': (840, 1440), 'note': (0, 1440) };

sealed class AssembleResult {}
class Placed      extends AssembleResult { final int startMin; }
class NeedDuration extends AssembleResult {}                     // 未估时
class CapacityFull extends AssembleResult { final int rem; }     // rem < dur
class NoSlot       extends AssembleResult { final List<int> suggestedDays; } // 换天建议（≤3）

/// 核心入口：为候选 c 在「当天正式卡集合 D」中找落点
AssembleResult findSlot({
  required List<TripItemRecord> dayItems,   // 仅正式卡（backupOf 排除由调用方过滤）
  required WishlistRecord candidate,
  required TripPace pace,
})
```

**findSlot 精确步骤**：
1. `d = candidate.durationMin`；`d == null → NeedDuration`；
2. `rem = kDayCapacity[pace] − Σ durationMin(D 中全体正式卡，含无 startTimeMin 者)`；`rem < d → CapacityFull(rem)`；
3. `L = D 中 startTimeMin != null 者的 [start, start+duration) 区间集`（duration 为 null 的已排卡视为占 60 分钟默认区间）；
4. `t` 从 420 到 `1440 − d`，步长 30 遍历：
   - 条件 A：`∀l∈L`，`[t, t+d) ∩ l = ∅`；
   - 条件 B：`t ∈ kTypeWindow[c.type]`（起点落在窗内即可）；
   - 首个满足的 `t → Placed(t)`；
5. 无命中 → `NoSlot(建议换天)`；建议换天由面板层调 `rankAlternativeDays`：对行程每天算 `rem'` 与窗口交集，取 rem' ≥ d 者按 rem' 降序取前 3。

**候选排序（池内默认展示序，纯函数 `rankCandidates`）**：
tag 权重 `必去=0 < 经典=1 < 小众=2 = 亲子=2 < null=3`；同分按 `|durationMin − rem|` 升序（未估时排最后）；再按 `sortOrder` 升序。窗口与当天完全无交集的候选置灰不可点（`windowIntersectsDay` 判定）。

### 10.3 UI 规格（三宿主）

- 面板结构：顶部当天选择（与时间轴 DayPicker 联动）；**容量条**（线性进度：`已排 X h / 容量 Y h`，X=ΣdurationMin 正式卡，备胎不计；X>Y 时条变警示色仍可用）；左栏想去池（复用 `wishlist_panel`，按 `rankCandidates` 排序、城过滤 chips 由 S11 注入）；右栏当天时间轴缩略（只读，高亮最近落点区间）；
- **点击即落点**：点击候选 → `findSlot` → `Placed` → 事务（建卡：startTimeMin=t、durationMin=d、guideRef/tag/name 继承、sortOrder 按时间序插入）+ 删池行 → toast「已排入 14:00 · 撤销」；

## 十一、S8 Plan B 备选项（A7）

### 11.1 数据语义（并列式，最终裁定）

- `backupOf` 非空（非 null 非 ''）= **有主备胎**：指向同行程内某正式卡 id；
- `backupOf == ''` = **无主备胎**（装配台「转备胎」产生，尚无挂靠对象）；
- 备胎仍带 `dateEpochDay`（预期那天）；时间轴**默认隐藏**，当天头部显示「备选 ×N」计数，点击展开灰显列表；
- 约束：至多一层（`backupOf` 指向的卡自身 `backupOf` 必须为 null，repo 写入时校验，违反抛 `StateError`）；同一正式卡可挂多个备胎；备胎不计入容量条、总览页、「有安排日」计数。

### 11.2 交互规格

| 动作 | 事务内容 |
|---|---|
| 正式卡「转为备选」 | 该天已有正式卡 → `backupOf = 该天首个正式卡 id`；该天无正式卡 → `backupOf = ''`；卡本身字段不变 |
| 装配台「转为备胎」 | 建卡 `backupOf=''`、日期=当前天、灰显；不删池条目？——**删池条目**（收口规则 1：已进日程体系） |
| **一键替换（互换身份）** | 同事务两行更新：正式卡 `backupOf = 备胎id`；备胎 `backupOf = null` 转正；**时间与日期字段不互换**（转正卡沿用自身 startTimeMin/durationMin）；toast「已替换 · 撤销」→ 单步撤销 = 再互换 |
| 备胎「转正（独立）」 | `backupOf = null`，直接成为正式卡（无主语义下等同） |
| 备胎「退回想去」 | 同事务：删卡（墓碑）+ 建 WishlistItems 行（继承 name/address/type/durationMin/guideRef/tag/cityKey，durationMin null 则带「未估时」） |
| 删除备胎 | 物理删 + 墓碑，无确认（低成本操作） |

### 11.3 同步与口径

- backupOf 随整行 LWW（S1 codec 已登记）；互换 = 两行各自 upsert 墓碑化无、按序入 outbox；
- 顺延引擎平移同正式卡（S2 已述）；
- PDF 总览页排除（S12 调用方过滤）；`trips_repo` 各统计/导出查询点统一增加 `backup_of 过滤`（列出全部现状读取点逐一核对：trip_detail 计数、trip_export、pdf 数据准备、trip_bill_linker 计划口径——最后者裁定：备胎**不参与**「计划 vs 实际」计划侧汇总）。

- 摘要 = 当天卡按 sortOrder 排序取前 3：有时间 → `HH:mm 名称`；无 → `名称`；>3 项尾部「…等 N 项」；空天 →「——」；
- **备胎一律不出现**（调用方过滤，构建器再防御性过滤一次）；
- 分页策略：**手动分块，22 行/块**，块间 `pw.NewPage()`，每块自带表头行（避免依赖 pdf 包表格跨页表头行为）；块高预算按行高 18pt 预留；
- 样式：复用 `_line/_muted/_mint/_surface` 既有常量与 `_textStyle`；DAY 徽记沿用内容页样式；

### T3 大纲文法速查

天头 `D<N>[:：]`；行 = `[HH:mm ]名称[ 时长]`；时长 `Xh / Xm / 半天 / 一天`（尾缀取最后）；无天头行 → 想去池；同名同天去重；导出与导入同文法对称；想去池/备胎不进导出。

### T4 术语表

| 术语 | 定义 |
|---|---|
| 想去池 | 行程内候选区（WishlistItems），条目无日期；落卡即移出 |
