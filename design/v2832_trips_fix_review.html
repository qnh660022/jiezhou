三张截图的病理报告

每一条都给出代码级根因，可在施工后逐条验收。

📷 截图 1 · 卡片发白 高 · 确诊

不是玻璃的锅。V2.8.2 S3「已结束降饱和」的矩阵写错了：

矩阵 [0.5,0.5,0.5] ⇒ R'=G'=B'=(R+G+B)/2
蓝 #4F8EF7 (79,142,247) ⇒ (234,234,234) 近白！

注释写的是 saturation 0.5，实际效果是「过曝提亮」：饱和蓝变成近白灰，白字 / 白 pill 全部不可读。正确做法是亮度保持的去饱和矩阵（0.213/0.715/0.072 系数）。

📷 截图 1 · 顶栏「灰板」 高 · 我的回归

3.1 我给玻璃加的「顶边受光高光」跨度算错了：LinearGradient(end: Alignment(0, 0.14)) 在 Alignment 坐标系里覆盖了 57% 高度（本意 10%），加上全宽 outlineVariant α0.35 深描边 → 吸顶栏成了压在页面上的灰板。修复：高光真 10% 跨度、描边按档位减淡、thin 档 tint 再降。

📷 截图 2 · 详情页逻辑混乱 中 · 重设计

① 玻璃 tab 胶囊悬在封面上=灰板；② 「已绑定旅行团」说明卡 + 5 图标大白卡占首屏 1/4，说明文案是噪音；③ 「行程概览」折叠卡、D1/D2 chips、每日安排三层重复导航；④ 信息层级无主次。→ 见 03 节重设计。

📷 截图 3 · funds_sync 报错 高 · 云端缺表

PGRST205 = Supabase 云端不存在 funds_sync 表——v2.7.1 的迁移 SQL（docs/db_v271.sql，含 funds_sync / inbox_items_sync 建表 + RLS）没有在 Supabase 执行过。客户端引擎推 funds 时命中缺表。数据侧需要你在 Supabase SQL Editor 执行 docs/db_v271.sql（我没有你的云端凭据，代不了手）；代码侧我会把硬报错转成人话 + 修复指引（见 05 节）。

🫥 行程卡乱序 高 · 确诊

三个因素叠加：
① 默认排序 recent 按 updatedAt 排——同步拉取 / 后台写入都会触碰它，顺序当场重排；
② Dart List.sort 非稳定排序，updatedAt 相同（如同步批次同毫秒写入）时每次重建顺序随机翻转；
③ StaggerIn(index) 随重建重播入场动画，把顺序变化放大成「乱跳」。

✅ 不背锅的部分

截图 2 详情页的蓝封面正常、截图 3 同步中心列表本身渲染正常；底栏胶囊、Sheet 类玻璃在两图中表现正常。本轮不动这些。

玻璃全 App 发白：根因确诊 + 已修复 ✅

你的反馈「所有玻璃特效全发白」就是确诊关键：全 App 同时发白 = 存在一层统一叠加在所有玻璃内容之上的东西。排查结论：3.1 我在 GlassSurface 里新增的 foregroundDecoration 白色渐变幕——前景层画在内容之上，白 α0.5 的渐变罩住上半截（且 Alignment 坐标算错实际覆盖 57% 高度）；玻璃收口是单点实现，51 处使用全部中招。叠加链：tint 白 + 对角柔光白 + 前景白幕 = 三层同向叠白 → 漂白。以下修复已施工完毕（代码已改，静态检查零诊断）：

层3.1 现状（事故）3.2 修复（已落地）
前景白幕
glass_surface.dart · 元凶		 白色渐变 α0.5 罩内容上半部 57%，全 App 玻璃同时发白 彻底删除渐变幕，前景只保留 1px 低 α 白受光环——「画在内容之上」的层从此永不放白色填充
对角柔光
内容之下的背景层		 白 α0.55，与 tint / 白幕三层同向叠白 α0.55 → 0.35（深色 0.22→0.18）
